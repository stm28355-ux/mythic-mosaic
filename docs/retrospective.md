# Mythic Mosaic 作りのふり返り（2026-11-24〜11-27）

11月24日から4日で、「六角の島に地形を置くと、形ができた所に幻の生き物が現れ、その生き物が土地を変えて連鎖する」一人用の箱庭パズルを作り、1.0.0 として公開した（工程0〜9）。企画はその前に別のチャットで固めた（生息地づくりゲーム 構想メモ → 企画まとめ 11/23）。途中で2つ目の島「火の山の島」を足し、生き物は24匹から48匹になった。Auto Battler・Arc-en-ciel Creator・Celestial Alchemy・Aether Atelier・Gateway Garden のふり返り（各リポジトリの `docs/retrospective.md`）の続きとして読む。

## 結論（先に3つ）

- **ルールの心臓部を「盤＋置く物 → 新しい盤と出た生き物」の純粋な関数にし、盤に「島の印」を持たせたのが最後まで効いた。** 連鎖問題の自動生成（全部の置き方を調べる）、スコアアタックの測り、エフェクト、新しい効果「押す」、2つ目の島が、全部同じ部品の上に乗った。2つ目の島の問題と地図は、盤に `island: 2` を足すだけでほぼ作れた。
- **判定表（Claude Docs、OK／直す／保留＋一言）を33回まわし、中身は人の判定で決めた。** 試作6匹 → 16匹 → 22匹、問題5問 → 12問、地図1面 → 2面と、少数で確かめてから量産した。人の一言（「島はパンパン」「生息域をデータで見たい」「湿地は終着点」）が、そのまま次の中身を決めた。
- **画面の採点で「画面の中の切り替え」を見落とし、人に「直し漏れていませんか」と言われた。** 図鑑の島や実績を切り替えると、枚（ダイアログ）ごと 100px 以上動いていた。中身が48匹・41問・45個に増えたのに一覧の形を変えず、図鑑は 4094px、挑戦は全部開くと 3978px あった。測り直してから、枚の大きさを決め、PC では横に並べ、挑戦はタブと1行にして直した（第30〜33回）。

## うまくいったこと

- **純粋な関数と、盤の「島の印」。** `place(盤, 場所, 置く物)` が段ごとの連鎖を返すので、問題の生成（`solveAll` で全部の置き方を調べる）、スコアアタックの測り（3人の遊び手）、エフェクト（段の前後の盤をくらべる）が同じ部品で作れた。押す効果は、段の最後にまとめて当てる1か所の追加で済んだ。2つ目の島は、盤に `island: 2` を持たせ、置ける物・出る生き物・広がり方をその印で分けた。問題・地図・生成の道具は、その印を渡すだけで火の山の島に広がった。
- **判定表を毎回作り、番号と一言で答えてもらった。** 33回とも、OK／直す／保留と短い一言で返ってきた。直すときは理由と直し方まで書いてあった（「湿地と同じ考え」「ハジマリは島の一番最後を飾る想定ですよね？」）。
- **少数で確かめてから量産した（前作の教訓）。** 生き物は試作6匹（第16・17回）→ 残り10匹を5匹ずつ → 足りない所に8匹。問題は入門3問 → 狙いごとに3段。火の山の島の問題は5問と地図1面を遊んでもらってから残り12問と2面。絵は見本6匹 → 18匹。
- **生息域のデータ（第21回）で、薄い所を人と一緒に見た。** 「どの物が使われていないか」「草の上の生き物の一覧」を区分ごとに数えて表にした。岩・巣・種が「隣」に一度も使われない、花は10匹が出すのに使うのは5匹、などが見え、人が「足したい／今のまま」を選んで8匹を足した。
- **決めごとをテストで守った。** 「問題はどの手も要る」「噂のない5匹から全部の噂にたどれる」「火の山の生き物は火の山の島にだけ出る」「入門は島ごとに先に並ぶ」「地図は置く前に形ができていない」。
- **道具で測ってから数字を決めた。** 問題の大きさ（19〜37マス・3手まで）は答え探しの速さから、スコアアタックの★は3人の遊び手（でたらめ・欲ばり・先読み）から決めた。人は「星は人の記録で直さない」と決められた。
- **game-ui（画面の採点）で、ずれを数字にした。** 測り直しのあとは、図鑑・挑戦・箱庭・問題・地図のどの切り替えでも、押す物のずれ 0px を PC とスマホで確かめた。

## 指示の出し方の評価

◎ とても良い　○ 良い（少し足すともっと良い）　△ 直すと良い

- ◎ **工程8の方向を、困っている理由と案つきで**（第14回のあと）。「島はパンパンだし、同じ要素から生き物を作ると挑戦が面倒。第2島を作って、特有の配置物、特有の何か（炎、隣の生き物を反対側に動かす効果とか）」。そのまま「火の山の島・押す」になった。
- ◎ **「出来ることは制限した方が良さそう」**（第16回）。置く物を島ごとに8つにする案②が決まり、画面も問題も複雑にならずに済んだ。
- ○ **「生き物が水か砂を出せば第2島でも水か砂が使えるように」**（第16回）。「使える」が置く物か形の材料か2通りに読めた。AI が確かめるべきだった。「手で置けるように／形に使えるように」と書いてあれば一度で済んだ。
- ◎ **「生き物の生息域を確認したい。区分を分けたデータで、足りなそうな部分に追加を検討できるように」**（第20回）。数えた表から、人が方針つきで足す所を選べた（「はじまりの島で増やすのは巣の生き物のみ」「湿地は終着点に近いもの」「押すは不要」）。
- ◎ **「漏れてそうなので全体的に見直し直してほしい」「挑戦は縦長すぎるので折りたたみ方も検討」**（第30回）。AI の見落としに気づき、範囲を広げて測り直すきっかけになった。
- ◎ **機能の追加を一言で**（第29回 Z7「スコアアタックのクリア手順を出力できるようにする」）。何を出すかがはっきりしていて、そのまま作れた。
- ◎ **見た目の気づきを理由の推測つきで**（第32回）。「タイルがつぶれているのは、下に2行の条件を書いているから？その場合、条件のあるマスはタイルを表示せず、解放条件だけ」。原因と直し方まで書いてあった。
- ◎ **判定の一言に、ゲームとしての考え方を書いた。** 「ハジマリは島の一番最後を飾る想定ですよね？」「湿地は作るのが難しい為、派生も少なくてOK。終着点に近いものとして捉える」。

## 人と AI の役割

- **人が強かったところ：** 遊びの方向（第2の島・押す・島ごとに8つ）、中身の考え方（湿地は終着点・巣ははじまりの島だけ・主は最後）、遊んで分かる不満（縦長・つぶれたタイル・切れた番号・外を押して閉じたい・挑戦から挑戦へ移りたい）、AI の見落としへの気づき。
- **AI が強かったところ：** ルールの心臓部とテスト、全部の置き方を調べる問題の生成、測る道具（住める数・答え探しの速さ・スコアの3人の遊び手・生息域の数え上げ）、ドット絵48匹、エフェクト、判定表と計画のメモの書き足し。
- **AI が弱かったところ：** 画面の中の切り替えまで測ること、直したあとの見た目を全部見ること、2通りに読める指示を確かめること、仕組みを足したときのほかの入口を探すこと。

## 次のゲームで使う手順

前作の24の手順に、今回の教訓を足した（25〜28）。

1. 好きなゲームの面白さを抜き出し、別のチャットで企画を固める。企画まとめ（Docs）を「正」にして、作るチャットにはリンクを渡す。
2. 企画に「変えないこと」と「ジャンルのお約束」を書く。
3. 中身の全体の形を表で決める。
4. 名前と見た目の方向を早めに決める。
5. フェーズは「中身を足す」「見た目」「最終の調整」を分ける。1フェーズは1〜2日で終わる大きさに。
6. フェーズごとに遊んで、番号と理由で答える。決まったことは計画のメモと企画まとめの両方に。
7. 「忘れないようにメモ」は Issue にし、マイルストーンを付ける。AI はフェーズを閉じる前に残りの Issue を並べる。
8. 大量に作るものは、人が見て直せる表やアーティファクトにする。試し描き・試作を数個見せてから量産する。
9. 調整の前提を決めてから、最後にまとめて合わせ、固定する。固定した数字はテストで守る。
10. 調整のあとに足すものは、「難易度を変えるか」を先に決める。
11. 操作の不満は小さくても、すぐ言う。
12. 長い計算は、締め切りと「寝る前にどこまで」を書く。
13. （パズル）素材や部品ごとに「いちばん素直な部品では、なぜだめか」を企画で1行書き、早めに確かめる。
14. （パズル）ソルバーの限界を最初に測り、大きさの上限をそこから決める。
15. （生成）量産の前に、計算の目安と人の順位が合うかを数問で確かめる。
16. （生成）「同梱するだけ」か「その場で作る」かを先に決める。
17. （工場・配置）新しい仕組みは、本編の前に試作の区画で1つずつ遊ぶ。中身の表の段階で、新しい仕組みの区画にお手本を1つ置いて広さを決める。
18. （調整）依頼や目標の量は、工夫する人の配置で決める。配置を文字列で渡せる仕組みを早めに入れ、人の配置をもらって量を測り、テストに入れる。
19. （調整）お手本の前提（最初の形か、改善した形か）を書き、報告で言う。人の計算とずれたら、まず前提を比べる。
20. （画面）中身を足すフェーズの終わりに、全ページ（タブ・図鑑・説明・地図）を見る。新しい道具や素材は、図鑑とマウスの説明を同じコミットで足す。分け方（タブ）は、最後の中身の数で決め直す。
21. （通信）通信のフェーズの終わりに、別の回線どうし（片方はスマホの携帯回線）で最後まで通す。合図の中継と TURN は最初に決め、つながらないときの確かめページを先に作る。
22. （画面）見た目の共通部品（背景・色・絵）は、どのページでも読む作りにする。見た目や言葉を変えたら、コミットの前に全ページを開く。遊び方とことばの一覧も同じコミットで直す。
23. （ルール）「席の順・最初の先番・同点」を、ルールの決めごとに入れる。1人と通信の両方で、席の偏りがないかを見る。守りのテストは席を回して揺れを抑える。
24. （画面）遊び方はゲームの流れの図つきで1つの部品にし、対戦中も開けるようにする。画面の直しは、採点（数字）→ 本物の画面に案を当てる → 人が選ぶ、の順で。
25. **（画面）採点の前に「画面と切り替えの一覧」（タブ・島・選ぶ・問題ごと・地図ごと）を作り、全部の組み合わせで押す物と枠の位置を比べる。** 枠（ダイアログ）は最初から大きさを決めて中でスクロールさせ、PC では横にも並べる。数字で測ったあと、直した画面を PC とスマホの写真で全部見る。
26. **（中身）中身を足したら、使われ方の表（中心・隣・出す・消す、島ごとに出られるか）を数えて人に見せ、薄い所を選んでもらってから足す。** 一覧の高さもそこで測り、形を決め直す。
27. **（中身）2つ目の島・区画は、盤に印を持たせ、その印を使う入口（置く物・出る生き物・広がり方・問題・地図・生成の道具・図鑑・実績）を一覧にして全部通す。** 新しい島の生き物は、形にその島にしかない物を必ず入れる。
28. **（図鑑）番号は足した順でなく、意味のある並び（島の最後に主）を先に決め、足すときに並べ直す。**

### 頼むときのひな形（今回の分を足した）

```
■目的：何を作る・直すか
■正の文書：企画まとめのリンク（決まったことはここに書き足す）
■変えないこと：遊びの柱、ジャンルのお約束、固定した数字 など
■前提：試すときの条件、遊び方（ふつうの人／工夫する人）、お手本は最初の形か改善した形か
■目標：数字と、その測り方（何を相手に、何回測るか）
■素材・部品の役目：それぞれ「いちばん素直な部品ではできないこと」
```
