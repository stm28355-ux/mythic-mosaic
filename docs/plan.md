## 作るときの決めごと

- ルールの心臓部（形の判定と連鎖）は「盤＋置く物 → 新しい盤と出た生き物」の純粋な関数にする（`src/core/`）。画面（`src/ui/`）はそれを呼ぶだけ。
- 乱数を使うときは種つき。同じ種なら同じ結果になる。
- 道具（測る・問題を作る）は `tools/` に置き、ゲームには出さない。報告では「ゲームに出る物か、道具だけか」を言う。
- 版は `package.json` と `src/version.js` をそろえる（テストで確かめる）。
- 画面や言葉を変えたら、コミットの前に全ページを開く。遊び方とことばの一覧も同じコミットで直す。
- コミットは自分のファイルを名前で足す（`git add -A` は使わない）。試しのまとめや設定はリポジトリの外（scratchpad か Claude Docs）に置く。
- 「忘れないようにメモ」は Issue にし、工程のマイルストーンを付ける。工程を閉じる前に残りの Issue を並べる。

## 工程0（2026-11-24）

- `src/core/hex.js`：六角の軸座標（隣・距離・六角の盤）と島の段。島は最後の61マスの左下の角に19マスで始まり、37 → 61 マスと右上へ広がる（第2回 F1）。
- `index.html`：島の広がり方の見本だけ。工程2で箱庭の画面に置き換える。

## 工程1（2026-11-25）

- `src/core/creatures.js`：生き物・地面・置ける物・解放の節目のデータ。形は「中心＋隣の条件」、効果は convert（地面を変える）・grow（木を生やす）・raise（高さを上げる）の3種類の組み合わせで書く。24匹に増やすときもルールは触らずデータを足す。
- `src/core/rules.js`：`place(盤, q, r, 置く物)` → `{ board, steps }`。段ごとに「変わったマスとその隣を調べる → 生き物を出す → 効果をまとめて当てる」をくり返す。`readyShapes`（置く前に何も起きない盤か）、`whyNotPlace`、`recordFound`、`unlocked`、`growIsland`。
- テスト27個。判定表の4連鎖の例（水1つでポチャ2匹 → コケダマ → ヌマヌシ → ケロリ）をそのままテストに入れた。
- 気づき：同じ段で2種類が同じマスを取り合って「どちらも出ない」になったマスでも、片方の種類が別のマスに出て使い終わると、次の段でもう片方だけがそのマスに住む。決めたルールどおりの動き（テストあり）。
- 試しの計算（scratchpad、ゲームにも道具にも入れていない）：置く前に何も起きない19マスの盤に水を置くと、何か出るのは15%、4連鎖は0.4%。工程3の測る道具で同じことを正式に測る。

## 工程2（2026-11-25）試作画面

- `index.html`・`src/ui/main.js`・`src/ui/view.js`：19マスの箱庭。置く物（草・水・砂、3匹で丘）を選んでマスを押す。連鎖は段ごとに「生き物が現れる → 土地が変わる」を 0.45 秒ずつ見せる。1手戻す・更地にする（図鑑は残る）・図鑑（見つける前は一言だけ）・遊び方（記録を全部消す）。記録はブラウザに保存（`mythic-mosaic:save`）。
- 生き物はまだ丸と番号（①〜⑥）。絵は工程7。高さは明るさ・影・▲で見せる。
- 見える範囲は今の島に合わせる（スマホ 375px で1マス約46px）。次に開く段は点線。
- `rules.place` が段の途中の盤（`spawnedBoard`）と後の盤（`board`）を返すようにした（画面が段ごとに見せるため）。
- 確かめたこと：ブラウザで水3つ → ポチャ、判定表の4連鎖の盤 → 4連鎖・丘が開く・島が37マス、図鑑、1手戻す。

### 試し遊びで見てほしいこと（1回6匹まで）

1. 一言のヒントだけで、6匹を見つけられるか（どれで詰まったか）。
2. 連鎖を「狙って組む」気になるか。偶然起きるだけか。
3. 段ごとの見せ方（速さ・何が変わったかの分かりやすさ）。
4. 操作の不満（押しにくい・戻したい所など）。

### 試し遊びの結果（2026-11-25、人）

1. 一言のヒントだけで6匹とも見つけられた。カゼノコだけはヒントでなく、いろいろ試していたら出た。
2. カゼノコが勝手に連鎖するので「悪用したくなる」。良い方向。
3. 段ごとの見せ方は分かる。
4. 操作の不満はなし。
- 思っていたより島がすぐ埋まる。生き物を島から帰す手段（回収）がどこかで要る（R8 で「後で」にしていた所）。

## 工程3（2026-11-25）測る道具

- `tools/measure.mjs`（道具だけ。ゲームには出ない）：`node tools/measure.mjs all 1` で 1. ばらばらな盤に1つ置いたときの連鎖、2. 61マスに同時に何匹住めるか、3. 答え探しの速さ を測る。結果は `docs/measure/phase3.md`。
- `src/core/search.js`：決まった順の置く物を全部の置き方で試し、一番長い連鎖を探す（いまは道具だけが使う）。`src/core/rng.js`：種つきの乱数。
- 結果の要点（試作の6匹）：
  - 適当に1つ置いて4連鎖以上は 1.2%（19マス）〜2.9%（61マス）。狙わないと長い連鎖は起きない。
  - 61マスは生き物でほぼ全部埋まる（ばらばらに300手で平均58匹、欲ばりなら50手で53匹）。広さは足りていて、埋まるのが速すぎる。
  - 答え探しは 37マス・3手で1盤0.25秒、37マス・4手で6秒、61マス・4手は約90秒（見積）。
- 判定表（第4回） https://claude.ai/artifact/4VAmQ32nGiGK5wJ6c2rSgK で、問題の大きさと手数・島の数・埋まり方への対応を決める。

## 工程4（2026-11-25〜）

### 回収「帰す」（#1、0.4.0）

- 置く物の並びに「帰す」（最初から使える）。選んで生き物を押すと島から帰る。
- 帰ったマスの地面・木・高さはそのまま。帰しただけでは連鎖は起こさない（形が残っていれば、次に隣が変わったときにまた出られる）。図鑑には残る。1手戻すで元に戻せる。
- `tools/measure.mjs` は回収なしで測ったので、帰すを置き方に入れない。

### 24匹の表（第5回、0.5.0）

- 24匹を7つの組に（水辺・草と森・花・砂と丘・岩と山・湿地・始まり）。データは `src/core/creatures.js`。
- 地面は5つのまま、上に乗る物に花・岩・巣を足した。置ける物は7つ（草・水・砂・丘・岩・巣・帰す）を2段に並べる。
- 新しい条件：「〜まで」（max・maxHeight）、生き物を条件に（id か「どれでも」）、一直線（⑨⑲だけ）。
- 新しい効果：高さを下げる・上の物を消す・生き物を帰す。効果で帰したマスは「変わった」に数え、連鎖が続く（人の「帰す」では続かない）。
- 解放：丘と37マスは3匹、岩は8匹、61マスは10匹、巣は⑫モリフクロを見つけたとき。
- 形が同じマスで重なる（D8 でどちらも出ない）のを避けるため、①②⑤を少し直した（①隣の水2〜4、②高さ0〜1で上に何もない草、⑤高さ0〜1の砂）。
- ⑥カゼノコのヒントを「丘を重ねたいちばん高い所で、草に囲まれて風を待っている」に（#2）。
- 確かめ：`tools/check-creatures.mjs`、結果は `docs/measure/phase4-creatures.md`。1手先を試す人で、毎回見つかるのは19匹、ときどき4匹（⑫⑬⑯㉔）、⑭ハナビラは「帰す→隣を変える」の2手が要る。
- 画面：花・岩・巣の絵、図鑑の形の文を条件から作る、効果で帰った生き物を段の文に出す。
- 気づき：段の途中の盤（spawnedBoard）が効果のあとの盤と中身を共有していて、段ごとの見せ方で効果が先に見えていた。写しを取るように直した（テストあり）。
- 試作の6匹のテスト（rules・search）は `CREATURES.slice(0, 6)` に固定。`tools/measure.mjs` も6匹のまま（工程3の数を変えないため）。

### 噂と実績（第6回、0.6.0）

- ヒントは4つの段：一言（最初から）→ 噂と使う物（噂を言う生き物を見つけたら。①②⑤は使う物を最初から）→ 光る所（新しい生き物が20手出ないとき）→ 形の全部（見つけたあと）。中身は `src/core/hints.js`、噂の文は `src/core/creatures.js` の rumor。
- 企画まとめでは「使う物」を「要る物が全部開いたら」出す約束だったが、24匹はほぼ最初から作れるので、噂と一緒に出すことにした（V4）。
- 光る所は、噂を聞いたまだの生き物が1手で出るマスを1つ（置く物は教えない）。新しい生き物が出たら消える。
- 実績は33個（`src/core/achievements.js`）。判定は「今の手の段＋手の前の盤＋手の後の盤＋図鑑」だけを見る。取ったら消えない、前の記録からは図鑑と島の実績をさかのぼって取る、取れたら右上に2秒。図鑑に「生き物／実績」のタブ。ふしぎ6個は取るまで？？？となぞかけ。問題とスコアの3個は工程5・6で判定を入れる。ごほうびの絵は工程7。
- 保存の形は 1 のまま。`achieved`（取った実績）と `dry`（新しい生き物が出ていない手数）を足し、無い保存は空で読む。
- 確かめ：`docs/measure/phase4-hints.md`。でたらめに置く人でも、光る所を使うと⑨⑯⑲㉑㉒㉓などが早く・多く見つかる。ただ、噂の無い②コケダマを見つけない人は森の組（⑩〜⑮）に進めず、光る所も出ない（光るのは噂を聞いた生き物だけなので）。⑫⑬⑭㉔は、でたらめな人では光る所を使っても見つからない。
- 気づき：`.book` の `display: grid` が `hidden` に勝って、タブで隠れなかった。`[hidden] { display: none !important; }` を足した。
- 0.6.1：人の答えで、光る所に噂のない①②⑤も含めた（使う物が分かっている生き物はみな光る）。でたらめな人で測り直すと、②コケダマは12回中8回→9回、⑫⑬も1回ずつ出た。でたらめな人は「1手で出る所」がある盤まで来ないことが多いので、光る所だけでは大きくは変わらない（狙って組む人には効くはず）。
